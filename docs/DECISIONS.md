# Decisions

One line each, oldest first (append new lines at the bottom). Format: `YYYY-MM-DD — decision — why`.

- 2026-11-03 — Schema is created with `create_all`, which never alters existing tables; a later column (e.g. job_id on scores) needs a migration step or a fresh database — found while weighing a sample tag for phase 3.
- 2026-11-03 — A refused or truncated document is not retried under the same consumer group; its batch offsets still commit — one bad paragraph must not wedge a 1.6 M-document run; whether to re-ask (other model, longer limit) or send it to a human queue is a phase 3 question.
- 2026-11-03 — Provider calls `messages.create` with `output_config.format` and reads `stop_reason` itself, not `messages.parse`; max_tokens 1024 — a truncated or refused answer becomes a per-document ReviewError instead of crashing the flow (run 2 died on a half-written JSON quote at 512).
- 2026-11-03 — Spend guard probes 20 attempts (ReviewErrors included, they are billed), takes the mean billed cost over all of them times the ids still to pull, and refuses above ELUSION_MAX_RUN_USD; 20 attempts with no verdict fail the run — a cheap probe before the bulk spend. The projection is an upper bound because `remaining` counts ids that will be skipped as already scored ($1.38 projected vs a lower actual rate).
- 2026-11-03 — Kafka consumer group name encodes criterion, model and prompt_version — a new prompt version starts from the beginning of the topic with no manual offset reset.
- 2026-11-03 — Scores are keyed on (doc_id, model, prompt_version) with ON CONFLICT DO NOTHING, and Kafka offsets commit only after the Postgres insert — a crash can never lose a stored score, and a re-pull of stored work is absorbed by the key at zero cost; a kill mid-batch does lose the in-flight batch's billed-but-unsettled reviews (at most batch_size - 1 documents), which the resume pays for again.
- 2026-11-03 — Review model is claude-haiku-5-5; judge is claude-opus-5-5 — Haiku 5.5 is $0.10/$0.50 per MTok, so 20k paragraphs cost well under $1; the API no longer publishes dated snapshot aliases, so the pinned id is the bare string and the `model` field the API returns is stored with every score as the actual snapshot.
- 2026-11-03 — doc_id = sha256(cik, year, text)[:16], not a paragraph index — re-splitting never renumbers existing documents, so idempotency survives splitter changes; identical paragraphs repeated in one filing collapse to one document.
- 2026-11-03 — Raw EDGAR-CORPUS is streamed, never stored; only Item 1A paragraphs are kept in Parquet — 1.8 GB/year raw vs a few hundred MB of paragraphs; re-download is the price of a re-collect.
- 2026-11-03 — Filing years 2018, 2019, 2020 — recent, Item 1A mandatory throughout, matches the CLAUDE.md example.
- 2026-11-03 — Compose image tags pinned (postgres 16.15, redpanda v26.2.6, mlflow v3.17.2, prefect 3.9.1) — reproducible stack; MLflow and Prefect server versions must track the client versions in uv.lock.
- 2026-11-03 — Host ports 5433 (Postgres) and 5001 (MLflow) in compose — 5432 and 5000 are taken on the dev Mac by Homebrew postgresql@17 and AirPlay Receiver; container ports unchanged.
- 2026-11-03 — Corpus is SEC 10-K Item 1A paragraphs (EDGAR-CORPUS), not Enron email — cleaner data, bigger, framed as a regulatory sweep; paragraphs keep the review shape and low richness.
- 2026-11-03 — Python only; no .NET component — simplicity; .NET is read, not written, for interview prep.
- 2026-11-03 — Prefect over Airflow — Python-native, runs in one container locally; Airflow understood from docs.
- 2026-11-03 — Spark (phase 5) and Pulumi (phase 6) are optional — cut first if time runs short.
- 2026-11-03 — Azure only in phase 6, torn down same day — cost ceiling ~$10 for cloud, ~$40 total.
- 2026-11-03 — Repo is public; secrets only in `.env` — learning artifact meant to be shown.
- 2026-11-04 — Criterion cloud-concentration tightened to cloud/hosting/data-center providers; suppliers, component vendors, payment processors excluded — v1 top hits were supplier risk; v1 scores kept for phase 4 comparison.
- 2026-11-04 — Price row for claude-opus-5-5 (judge model): $4 input, $20 output, $5 cache write (5m), $0.20 cache read per MTok — source: https://platform.claude.com/docs/en/about-claude/pricing (fetched 2026-11-04; claude-api skill agrees on input/output/cache read).
- 2026-11-04 — Flag line is score >= 3, not 2 — level 2 means a provider is mentioned without dependence risk, so it is a non-hit by definition; 119 of the first 161 v2 paragraphs at >= 2 were 2s.
- 2026-11-03 — In phase 3 the judge model (claude-opus-5-5, effort low, prompt `cloud-concentration/judge-v1`) labels the gold set and the owner's 20 blind labels audit the judge — the owner can label about 20 paragraphs, not 300; the report shows the judge's metrics and its agreement with the owner, and says an LLM judged an LLM. Phase 4's judge item (grading rationales) is a different use and stays there.
- 2026-11-03 — Two piles: the judge labels every flagged paragraph and a uniform seeded sample of 200 from the discard pile; precision and elusion are direct proportions, richness and recall are combined from the two piles weighted by pile size — positives are rare (117 of 12,906 v1 scores were 2 or more), so a uniform gold sample of 300 would hold about three; the flag line is recorded separately (score >= 3, 2026-11-04).
- 2026-11-03 — Population is every document with a score for the (review model, prompt version) pair; no sample column on `scores`, and `--sample N` stays "the next N ids for the consumer group" — closes the phase 2 open question; the report says "population", never "corpus", because the first 20,000 topic ids are in ingest order, not a random draw.
- 2026-11-04 — Recall and richness intervals are derived by evaluating the formula at the Clopper-Pearson bounds of precision and elusion, and labeled "derived from the two pile intervals"; they cover at least about 90% (0.95 x 0.95), not 95% — both are monotone in the two inputs and the samples are independent.
- 2026-11-04 — Reports are written to `docs/reports/<criterion>-<model>-<version>.md` and committed — the report is the artifact the project exists to produce; phase 4 logs the same file to MLflow.
- 2026-11-05 — Phase 4 runs vary model and prompt version, not temperature — Haiku 5.5 takes no temperature, OpenAI small models reject it, and a sweep would force a generation-settings column into the scores key; settings are logged as MLflow params instead.
- 2026-11-05 — The registered model `elusion-reviewer` is a pyfunc wrapper around the reviewer configuration (provider, pinned model, prompt version, threshold, settings); promotion is the MLflow alias `champion`, and `review --reviewer name@alias` resolves it — a registry version that can score is what a registry is for; stages are deprecated in MLflow 3.
- 2026-11-05 — Ollama is driven through its OpenAI-compatible endpoint with the `openai` SDK, which moves from optional extra to dependency — one client for both new providers, no new top-level package.
- 2026-11-05 — Rationale grades live in `data/grades/<criterion>.csv`, keyed by (doc, review model, prompt version, grader), never in the gold CSV — grades judge a reviewer's reasoning, gold labels judge a document; the grader never sees a label.
- 2026-11-05 — One MLflow run per `evaluate`, no dedupe — evaluate spends no tokens and a run is the record of an attempt; the latest run for a pair is the current one.
- 2026-11-05 — The discard sample for a pair is the seeded draw from that pair's own discard pile, recomputed in `evaluate` — "every labeled doc below the threshold" was uniform with one run but would be enriched by other runs' flagged docs once there are several.
- 2026-11-04 — Public docs (README, docs/DEFENSIBLE-REVIEW.md) report recall as "not established, [0.05, 1.00]", never the 1.000 point estimate — the point estimate is an artefact of k=0 in the discard sample; the 2,500-label elusion sample that would bound it is not run.
- 2026-11-05 — OpenAI review model is gpt-6-luna at $0.10/$0.01/$0.50 per M tokens (input/cached input/output), source https://developers.openai.com/api/docs/pricing and https://developers.openai.com/api/docs/models/gpt-6-luna — the small low-latency tier (same list price as Haiku 5.5, so the comparison is quality at equal cost); supports structured outputs and prompt caching on the Responses API. OpenAI lists no dated snapshot for it (the only snapshot id is `gpt-6-luna` itself), so the echo check is the guard if that changes; the dated alternative `gpt-5.4-nano-2026-03-17` ($0.20/$0.02/$1.25) is marked deprecated. Installed `openai` SDK 3.43.0.
- 2026-11-06 — Ollama review model is qwen2.5:14b, digest sha256 7cdf5a0187d5c58cc5d369b255592f7841d1c4696d45a8c8a9489440385b22f6 (Q4_K_M, 14.8B parameters, Ollama 0.40.14, from `GET /api/tags` on 2026-11-06), run on the dev Mac — non-thinking instruct model (no reasoning tokens to break schema-constrained JSON), 9.0GB, "tools" capability, https://ollama.com/library/qwen2.5; zero cost, wall-clock is the price.
- 2026-11-06 — Prompt v3 adds one rule per phase 3 gap, keeping v2's 0-4 scale and JSON fields so the comparison isolates the rules: third-party SaaS counts only as dependence on one or a few named or described providers to operate; an ISP counts only if it also hosts or colocates; generic IT outsourcing does not count whether or not the vendor is named (unless it is a hosting, cloud or data-center provider, then the main criterion applies); mixed on-site plus cloud counts only when the cloud part is a dependency on one or a few providers. A fifth clarification beyond the four gaps: vendors managing parts of the company's own facilities do not count unless they run its hosting. Why: the owner/judge disagreements on score-3 paragraphs were all cases with no stated reliance on one or a few providers. The criterion line moved for named SaaS dependence (`criteria/cloud-concentration.md` now admits it); the other rules clarify the existing line. v1 and v2 are never edited.
- 2026-11-06 — The judge stays on `judge-v1` for every pair, v3 included, although task 8 widened the criterion to admit named SaaS dependence and `judge-v1.md` states the old line — one answer key across all five runs keeps them comparable. The v3 report and the phase note count the v3 flags the judge rejected whose rationale cites a SaaS vendor; if that count is material, a `judge-v2` with the moved line and a relabel follow. The grader (`grade-v1`) states judge-v1's criterion for the same reason.
- 2026-11-07 — Review time in reports and MLflow (`review_wall_clock_s`, `docs_per_minute`) is each review_jobs row's duration summed, not first start to last finish — failed 0-doc starts (gpt-6-luna) and a probe 1.5 h before the main run (qwen2.5:14b) put idle gaps into the span: 21:27:58 for a 1:24:57 run.
- 2026-11-07 — Champion is gpt-6-luna with prompt v2 (`elusion-reviewer` version 1, from MLflow run bd1d61f365b94f8e818110d045e5f6a0) — by the spec's rule: every pair's elusion upper bound is 0.018, so the best precision wins (0.511 [0.358, 0.663]); cost was not needed as a tie-break. The precision intervals of all five runs overlap, so this is a choice, not a proven ranking.
- 2026-11-07 — `elusion promote` registers the run's logged model by its id (`models:/<model id>`, found by source run), not `runs:/<run id>/reviewer` — MLflow 3 stores a logged model apart from the run's artifacts, and the `runs:/` form only works through a deprecated fallback.
- 2026-11-07 — Report filenames map every character Windows rejects (`<>:"/\|?*`) to `-`, so `qwen2.5:14b` writes `cloud-concentration-qwen2.5-14b-v2.md` — a colon in a committed path makes a Windows clone of this public repo fail at checkout.
- 2026-11-11 — Phase notes use four new headings from phase 4 on (What we built / Why we built it / What we learned / Results); the old four included two written for an outside audience (the production-platform contrast, the question for their team) and left no room for what was actually learned. Notes 0–3 keep the old headings.
- 2026-11-15 — Phase 6 (Azure) is next; a new phase 7, the literature matter, follows it; phase 5 (Spark) stays optional and uncut — Azure is the gap `docs/PROJECT.md` names, it is bounded at about three days and does not depend on the corpus, while the new matter is open-ended and would crowd it out if it came first.
- 2026-11-15 — Phase 7 is a second corpus about the project's own subject (AI agents making decisions that must be auditable): harvest abstracts broadly, screen them with the existing review, judge and evaluate flows against a new criterion, then answer questions from the screened-in set with every step logged. The 10-K matter stays. Why broad harvest plus screening and not one search term: no single term covers the topic. OpenAlex counts for works published since 2023-01-01, taken 2026-11-15 with the `search` parameter (title, abstract and full text): "technology-assisted review" 374, "high-recall retrieval" 184, "citation screening" 1,220, "e-discovery" or "electronic discovery" 2,298, "automated decision-making" 31,071, "LLM-as-a-judge" 25,834, "predictive coding" 27,709 (also a neuroscience theory; not sampled). A broad harvest keeps richness low, so recall, precision and elusion keep their meaning. Sources are open ones only (OpenAlex abstracts, arXiv, CourtListener opinions); news articles are copyrighted.
- 2026-11-15 — In phase 6 Postgres, Redpanda and the Prefect server run as pods in the AKS cluster from the Helm chart, mirroring `compose.yaml`; the Parquet text goes in the blob container; no managed Azure database or Event Hubs — Terraform stays at the resources in the checklist, it is the most Helm and Kubernetes practice, and it is the easiest to finish and destroy in one day.
- 2026-11-15 — Phase 6 Terraform includes a $10 resource-group budget with an email alert (address supplied at apply time, never committed), and the region is West US 2 — a cluster left running costs about $5.50 a day; the list prices in the spec were read for that region.
- 2026-11-15 — The phase 6 cluster run reviews filing year 2020 — no model has a local score for any 2020 document (every v2 and v3 pair holds 15,875 documents from 2018 and 2,061 from 2019), so nothing already paid for is paid for again.
- 2026-11-15 — Scores from the cluster run are evaluated as their own population, by filing year, not merged into the champion's report; the owner left the choice to the controller's recommendation — merging would leave the leaderboard no longer like for like and overwrite the report the promotion rests on, and a year filter (one or more years) keeps the existing reports reproducible as 2018 and 2019. The filter is designed in an addendum to the phase 6 spec before it is built.
- 2026-11-15 — The owner confirmed the phase 6 spec's fourteen controller's calls; the lines below record the ones not already above. The 2020 run's report states its population as the first 20,000 paragraphs of 2020 in ingestion order — that is not a random draw from the year, and the metrics describe that population only.
- 2026-11-15 — The cluster run names the champion by its parts (openai, gpt-6-luna, v2), not `--reviewer`; MLflow and its registry stay local — the registry is not deployed to the cluster. On the day `elusion-reviewer@champion` is resolved locally and compared with the parts before the run starts.
- 2026-11-15 — Before the destroy, `scores` and `review_jobs` are exported from the cluster's Postgres and loaded into the local one — the local ledger must know every document that has been paid for. Job ids are UUIDs, so cluster rows cannot collide with local ones.
- 2026-11-15 — `review_jobs` gains a nullable `run_env` column set from `ELUSION_RUN_ENV` (default `local`), added to an existing table by an idempotent `ALTER TABLE` in `ensure_schema` — where a decision was made is part of its audit trail, and it is how the report names the cluster.
- 2026-11-15 — The image and chart are rehearsed on OrbStack's Kubernetes with the local Ollama model before any Azure resource exists; the rehearsal's scores are discarded — Azure time costs money and the destroy is the same day, so the Azure day should be a runbook, not a debugging session.
- 2026-11-15 — On the cluster a flow run is a Kubernetes Job started by a Prefect worker from one Kubernetes work pool; the worker runs from Prefect's own Kubernetes image at the pinned version, so `pyproject.toml` gains no dependency — the review is a batch job, and its service form is a Job per run.
- 2026-11-15 — No cluster Service is exposed to the internet; the Prefect UI and Postgres are reached with `kubectl port-forward` — a one-day cluster needs no ingress, and nothing public means nothing to secure.
- 2026-11-15 — The chart references its two Secrets (OpenAI key, Postgres password) by name and never creates one from a value; the owner creates them with `kubectl`. The OpenAI key is made for this run and revoked after the destroy — a key that reached a cluster should not outlive it.
- 2026-11-15 — Terraform state is local and gitignored; the subscription id comes from `ARM_SUBSCRIPTION_ID`; `.terraform.lock.hcl` is committed — everything is destroyed the same day, so a remote state store would buy nothing.
- 2026-11-15 — The cluster is two `Standard_D2s_v5` nodes on the free control-plane tier; the image is built for arm64 and amd64 and pinned by digest on AKS; node size is a Terraform variable and task 0 checks the size is not restricted — a capacity refusal on the day is then a one-line change.
- 2026-11-15 — The corpus directory is a mounted volume (the blob container through the Blob CSI driver on AKS, an ordinary volume on the laptop cluster), not a storage library — `load_texts` and `write_parquet` already read and write a directory.
- 2026-11-15 — The blob mount cannot be rehearsed on OrbStack, so the Azure day starts with a five-document `collect` as its smoke test; if the mount does not work within an hour the corpus volume becomes a managed disk and the Parquet file is uploaded to the blob container afterwards.
- 2026-11-15 — A flow-run Job never retries on its own, and recovery after a failure is to reset the consumer group to the start of the topic and start the same `sample=20000` run again — `sample` counts ids pulled from the committed offset, so an automatic retry would score 20,000 further documents, while a reset run skips every scored id and pays only for the rest. This replaces the first draft's "run the remainder", which needed arithmetic on paid time.
- 2026-11-15 — Pulumi stays optional and last in phase 6, with its own short spec if it is done.
- 2026-11-15 — The phase 6 budget is two $10 budgets, one on the resource group and one on the AKS node resource group — AKS puts the node machines, disks and networking in a second group it creates itself (https://learn.microsoft.com/en-us/azure/aks/faq), so a budget on the main group alone would not see a forgotten cluster.
