# Decisions

One line each, newest first. Format: `YYYY-MM-DD — decision — why`.

- 2026-11-03 — Schema is created with `create_all`, which never alters existing tables; a later column (e.g. job_id on scores) needs a migration step or a fresh database — found while weighing a sample tag for phase 3.
- 2026-11-03 — A refused or truncated document is not retried under the same consumer group; its batch offsets still commit — one bad paragraph must not wedge a 1.6 M-document run; whether to re-ask (other model, longer limit) or send it to a human queue is a phase 3 question.
- 2026-11-03 — Provider calls `messages.create` with `output_config.format` and reads `stop_reason` itself, not `messages.parse`; max_tokens 1024 — a truncated or refused answer becomes a per-document ReviewError instead of crashing the flow (run 2 died on a half-written JSON quote at 512).
- 2026-11-03 — Spend guard probes 20 attempts (ReviewErrors included, they are billed), takes the mean billed cost over all of them times the ids still to pull, and refuses above ELUSION_MAX_RUN_USD; 20 attempts with no verdict fail the run — a cheap probe before the bulk spend. The projection is an upper bound because `remaining` counts ids that will be skipped as already scored ($1.38 projected vs a lower actual rate).
- 2026-11-03 — Kafka consumer group name encodes criterion, model and prompt_version — a new prompt version starts from the beginning of the topic with no manual offset reset.
- 2026-11-03 — Scores are keyed on (doc_id, model, prompt_version) with ON CONFLICT DO NOTHING, and Kafka offsets commit only after the Postgres insert — a crash can never lose a stored score, and a re-pull of stored work is absorbed by the key at zero cost; a kill mid-batch does lose the in-flight batch's billed-but-unsettled reviews (at most batch_size - 1 documents), which the resume pays for again.
- 2026-11-03 — Review model is claude-haiku-5-5; judge is claude-opus-5-5 — Haiku 5.5 is $0.10/$0.50 per MTok, so 20k paragraphs cost well under $1; the API no longer publishes dated snapshot aliases, so the pinned id is the bare string and the `model` field the API returns is stored with every score as the actual snapshot.
- 2026-11-03 — doc_id = sha256(cik, year, text)[:16], not a paragraph index — re-splitting never renumbers existing documents, so idempotency survives splitter changes; identical paragraphs repeated in one filing collapse to one document.
- 2026-11-03 — Raw EDGAR-CORPUS is streamed, never stored; only Item 1A paragraphs are kept in Parquet — 1.8 GB/year raw vs a few hundred MB of paragraphs; re-download is the price of a re-collect.
- 2026-11-03 — Filing years 2018, 2019, 2020 — recent, Item 1A mandatory throughout, matches the CLAUDE.md example.
- 2026-11-03 — Compose image tags pinned (postgres 16.15, redpanda v26.2.6, mlflow v3.17.2, prefect 3.9.1) — reproducible stack; MLflow and Prefect server versions must track the client versions in uv.lock.
- 2026-11-03 — Host ports 5433 (Postgres) and 5001 (MLflow) in compose — 5432 and 5000 are taken on the dev Mac by Homebrew postgresql@17 and AirPlay Receiver; container ports unchanged.
- 2026-11-03 — Corpus is SEC 10-K Item 1A paragraphs (EDGAR-CORPUS), not Enron email — cleaner data, bigger, framed as a regulatory sweep; paragraphs keep the review shape and low richness.
- 2026-11-03 — Python only; no .NET component — simplicity; .NET is read, not written, for interview prep.
- 2026-11-03 — Prefect over Airflow — Python-native, runs in one container locally; Airflow understood from docs.
- 2026-11-03 — Spark (phase 5) and Pulumi (phase 6) are optional — cut first if time runs short.
- 2026-11-03 — Azure only in phase 6, torn down same day — cost ceiling ~$10 for cloud, ~$40 total.
- 2026-11-03 — Repo is public; secrets only in `.env` — learning artifact meant to be shown.
- 2026-11-04 — Criterion cloud-concentration tightened to cloud/hosting/data-center providers; suppliers, component vendors, payment processors excluded — v1 top hits were supplier risk; v1 scores kept for phase 4 comparison.
- 2026-11-04 — Price row for claude-opus-5-5 (judge model): $4 input, $20 output, $5 cache write (5m), $0.20 cache read per MTok — source: https://platform.claude.com/docs/en/about-claude/pricing (fetched 2026-11-04; claude-api skill agrees on input/output/cache read).
- 2026-11-04 — Flag line is score >= 3, not 2 — level 2 means a provider is mentioned without dependence risk, so it is a non-hit by definition; 119 of the first 161 v2 paragraphs at >= 2 were 2s.
- 2026-11-03 — In phase 3 the judge model (claude-opus-5-5, effort low, prompt `cloud-concentration/judge-v1`) labels the gold set and the owner's 20 blind labels audit the judge — the owner can label about 20 paragraphs, not 300; the report shows the judge's metrics and its agreement with the owner, and says an LLM judged an LLM. Phase 4's judge item (grading rationales) is a different use and stays there.
- 2026-11-03 — Two piles: the judge labels every flagged paragraph and a uniform seeded sample of 200 from the discard pile; precision and elusion are direct proportions, richness and recall are combined from the two piles weighted by pile size — positives are rare (117 of 12,906 v1 scores were 2 or more), so a uniform gold sample of 300 would hold about three; the flag line is recorded separately (score >= 3, 2026-11-04).
- 2026-11-03 — Population is every document with a score for the (review model, prompt version) pair; no sample column on `scores`, and `--sample N` stays "the next N ids for the consumer group" — closes the phase 2 open question; the report says "population", never "corpus", because the first 20,000 topic ids are in ingest order, not a random draw.
- 2026-11-04 — Recall and richness intervals are derived by evaluating the formula at the Clopper-Pearson bounds of precision and elusion, and labeled "derived from the two pile intervals"; they cover at least about 90% (0.95 x 0.95), not 95% — both are monotone in the two inputs and the samples are independent.
- 2026-11-04 — Reports are written to `docs/reports/<criterion>-<model>-<version>.md` and committed — the report is the artifact the project exists to produce; phase 4 logs the same file to MLflow.
- 2026-11-04 — Public docs (README, docs/DEFENSIBLE-REVIEW.md) report recall as "not established, [0.05, 1.00]", never the 1.000 point estimate — the point estimate is an artefact of k=0 in the discard sample; the 2,500-label elusion sample that would bound it is not run.
